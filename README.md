# RetailCast India — 28-Day Demand Forecast

Forecasts 28 days of daily unit demand (`d_1914`…`d_1941`) for 60 product-store series for
RetailCast India. The model is a hybrid: a trailing-window per-series statistical model for the
15 series with a documented regime change, and a pooled XGBoost model for the other 45 — see
`approach_summary.md` (Q2/Q4) for why.

## Structure

```
.
├── retailcast_config.json   # tells the eval agent how to run this pipeline
├── pipeline.py               # forecasting pipeline entry point (hybrid model, see below)
├── gbm_model.py               # pooled XGBoost/Tweedie model used for the 45 non-regime series
├── backtest.py                # reproduces the Q5 validation table (multi-origin backtest)
├── requirements.txt          # pinned dependencies
├── submission.csv            # committed fallback forecast (regenerated by pipeline.py)
├── data/                      # input data (sales_train, calendar, sell_prices, vendor feeds)
├── chat_export.md            # Phase 1–2 investigation, exported from Claude
└── approach_summary.md       # Technical Decision Log (the seven required questions)
```

## Running it

```bash
pip install -r requirements.txt
python3 pipeline.py --data data --out submission.csv
```

This reads `data/sales_train.csv`, `data/calendar.csv`, and `data/sell_prices.csv`
(the last is a target-day feature for the pooled GBM only — see Q2/Q4 for why it's otherwise
excluded), and writes `submission.csv` with columns `id, F1..F28`. Row order doesn't matter;
ids match `data/sample_submission.csv` verbatim.

## Validating the format

```bash
python3 validate_format.py --submission submission.csv --sample data/sample_submission.csv
```

## Reproducing the validation numbers

```bash
python3 backtest.py --data data
```

Runs the same 9-origin backtest cited in `approach_summary.md` Q5.

## Data files intentionally not used

- `market_signal.csv` — excluded. It has zero coverage of the forecast horizon (only
  `d_1..d_1913`), and per-series it is a near-deterministic linear rescaling of same-day sales
  (correlation 0.87–0.96, and it is exactly 0 whenever sales are 0). It's target leakage
  dressed up as a feature, not an independent signal.
- `vendor_signal.csv` — excluded. It does cover the horizon, but historically tracks actual
  sales weakly (mean per-id correlation ~0.12, ~50.5% median MAPE (~75% mean) over the trailing
  90 days, excluding zero-sales rows) — not trustworthy enough to include as a model input.

Full reasoning, evidence, and the seven-question decision log are in `approach_summary.md`
and the accompanying chat export.

## Model selection

I tested a pooled XGBoost/Tweedie direct-multistep model against the per-series trailing-window
baseline on the same 9-origin backtest scheme. Neither wins outright pooled across all 60
series, but segmenting error by regime status showed the baseline wins on the 15 regime-flagged
series and the pooled XGBoost wins on the other 45 — routing each segment to its stronger model
(`pipeline.py`'s actual logic) beats either pure single-model approach. See
`approach_summary.md` Q4/Q5 for the numbers.
